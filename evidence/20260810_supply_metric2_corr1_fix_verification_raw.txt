## 見つかった問題（Codex受入監査からの指摘、原文要約）

1. SPEC.md §15.4.3手順5「exact_times=1の行がある場合は、時刻範囲が正で割り切れることを
   検証し」は文字どおりの整除要求である。旧実装は3900秒/600秒（余り300）を7便のmeasuredと
   誤って算出していた。正しくはscheduled_trip_count_by_dateをinvalid_inputにすべき。
2. SPEC.md §15.2・§15.4.3が要求するtrips.txtの参照整合性検証が欠落していた。
   - 未知のservice_id（calendar.txt/calendar_dates.txtに存在しない）を参照するtripが
     measured 0（無視されるだけ）になっていた
   - 未知のroute_id（routes.txtに存在しない）を参照するtripがmeasured 1（無視されず
     普通にカウントされる）になっていた
   - route_id列が丸ごと無いtrips.txtがmeasured 1になっていた

追加した。


修正後:
```python
            exact = row[exact_idx2] if (exact_idx2 is not None and exact_idx2 < len(row)) else ""

                return None, f"frequencies.txtのtrip_id '{tid}' のexact_timesが不正: {exact!r}"
```


### 修正2: route_id/service_id参照整合性

`_prepare_trip_count_context()`のシグネチャに`routes: FileTable`引数を追加し、
